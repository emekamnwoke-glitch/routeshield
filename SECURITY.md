# Security Policy

## Scope of this document

RouteShield is a portfolio project containing an enterprise architecture and a fictional reference implementation. It processes no real personal data, holds no real credentials, and connects to no real operational system.

That does not make security irrelevant here. The security architecture is one of the artefacts this project exists to demonstrate, and the repository itself is held to the standard it describes.

## What this repository must never contain

- Real API keys, tokens, passwords, connection strings or certificates
- Real personal data of any kind, including test data derived from real people
- Real operational data belonging to any transport operator
- Any credential that grants access to a system outside this repository

Configuration is supplied through environment variables. Every configurable value has an entry in a committed `.env.example` carrying a placeholder, never a working value.

## Secret scanning

Pull requests run automated secret detection. A pull request that trips the scanner does not merge. If a secret is ever committed, the correct response is to rotate the credential first and rewrite history second — history rewriting alone does not undo exposure.

## Data in this repository

All datasets are either **open** (published under a licence permitting reuse — NTA GTFS, OpenStreetMap) or **synthetic** (generated by the pipeline in this repository). Synthetic files are labelled as synthetic in the file itself, not only in the directory name, so that a file cannot be mistaken for real data once separated from its folder.

No dataset in this repository describes a real individual, a real vehicle, a real driver or a real journey.

## Reporting a vulnerability

If you find a security problem in this repository — an exposed secret, a vulnerable dependency, an injection flaw in the demonstrator — please open a GitHub issue. Given the nature of the project there is no embargo process and no security contact address; there is nothing here whose compromise would harm anyone.

If the finding concerns something that could harm a third party, please raise it privately through GitHub's private vulnerability reporting instead of a public issue.

## Threat model

The threat model for the *architecture* — covering authentication, authorisation, service-to-service trust, API security, data protection, audit integrity, least privilege and supply chain — is developed in Phase D of Stage One and in `docs/02-stage-two-reference-implementation/security/`. It is deliberately larger in scope than the threat model for this repository, because it describes the system that would need to exist, not the demonstrator that does.
